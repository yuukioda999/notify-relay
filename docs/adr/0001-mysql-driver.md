# ADR-0001: MySQL への接続に go-sql-driver/mysql を使う

- ステータス: 提案中
- 日付: 2026-11-05
- 決定者: 小田 裕貴
- 関連: team-ops ADR-0004(専用スキーマ)、CLAUDE.md「外部ライブラリは必要最小限」

## コンテキスト

- 受け付けた配信依頼と宛先は、再起動しても失わないよう MySQL の専用スキーマに保存する(team-ops ADR-0004、AC-R001-01・13)
- Go の標準ライブラリには `database/sql` のインタフェースだけがあり、MySQL と話すドライバーは含まれていない
- 外部ライブラリは必要最小限にし、追加するときは理由をADRに書く

## 検討した選択肢

| 案 | 内容 | 評価 |
|---|---|---|
| **A** | **go-sql-driver/mysql(`database/sql` のドライバー)** | **Go で MySQL を使う事実上の標準。依存は1つ(filippo.io/edwards25519、認証方式のため)だけ。`database/sql` の上で動くので、他の部分は標準ライブラリのまま書ける** |
| B | ORM やクエリビルダー(GORM、sqlc など)を使う | 書く量は減るが、依存とコード生成が増える。テーブルは2つだけで、SQLを直接書くほうが行のロック(`FOR UPDATE SKIP LOCKED`)を明示しやすい |
| C | ドライバーを自作する | 現実的でない |

## 決定

案Aを採用する。

- 使うのは `database/sql` と go-sql-driver/mysql だけ。SQL は `internal/infra/mysqlstore` に直接書く
- マイグレーションも外部ツールを使わず、埋め込んだ SQL ファイルを起動時に順に流す小さな仕組みで行う

## 結果

良くなること:

- 依存が少なく、govulncheck と Dependabot で追う対象も少ない
- 行のロックやトランザクションの範囲を SQL で明示でき、二重送信の防止(AC-R001-08・13)をテストで確かめやすい

悪くなること・受け入れるコスト:

- SQL と Go の型の対応を手で書く。テーブルが増えたら sqlc などのコード生成を検討する

## 見直す条件

- テーブルやクエリが増え、手書きの SQL の保守が負担になった場合
